# 115 目录秒传上传（U115AutoUpload）

实时监控本地目录，发现新文件后先多次探测 115 秒传；全部未命中后再走普通上传。

- 仅支持 MoviePilot V3。
- 复用主程序“设置 → 存储”里已登录的 115 授权，插件内不需要再填账号。
- 秒传探测使用 115 的 `fileid`（全文件 SHA1）和 `preid`（前 128MB SHA1）。
- 同一次文件上传中，哈希只计算一次并缓存，后续探测不再重复读文件。
- 使用插件自有数据库记录已处理文件，保证不重复上传。
- `watchdog` 实时监控 + 定时扫描双保险，网络盘收不到事件时由定时扫描兜底。
- 详情页提供处理记录列表，支持重试、删除记录、清理成功记录和立即扫描。

## 安装

MoviePilot 插件市场 → 添加仓库：

```text
https://github.com/yating1022/MoviePilot-Plugins
```

然后安装 `U115AutoUpload`。

## 数据库

不需要手动建表。插件通过 MoviePilot 的插件自有数据库声明模型，宿主会自动建表：

- PostgreSQL schema：`plugin_u115autoupload`
- 表名：`upload_record`

建表发生在插件加载时（`get_database_models`）和插件配置初始化时（幂等 `create_all`）。
数据库账号需要对插件 schema 有 `USAGE` 和 `CREATE` 权限；权限不足时日志会明确报错。

查看记录：

```sql
SELECT id, local_path, status, method, remote_path, retry_count, updated_at
FROM plugin_u115autoupload.upload_record
ORDER BY updated_at DESC
LIMIT 200;
```

`status` 取值：

- `success`：上传成功
- `failed`：上传失败，可重试
- `pending`：已加入重试队列
- `skipped`：首次启用时已存在的文件，不执行上传（不在列表页显示）

如果不想用插件自有表，而是想复用你手动创建的表，也可以改成原生 SQL；但推荐使用插件 schema，避免和宿主表混在一起，也方便卸载插件时自动清理。

## 配置

| 配置项 | 说明 |
| --- | --- |
| 启用插件 | 开启后才会启动实时监控和定时扫描 |
| 保存后立即运行一次 | 保存配置后 2 秒立即扫描一次，开关会自动关闭 |
| 启用实时监控 | 使用 watchdog 监听文件变化；网络盘可能收不到事件，仍由定时扫描兜底 |
| 本地监控目录 | MoviePilot 容器内的路径，例如 `/downloads/watch` |
| 115 目标目录 | 115 网盘内的路径，例如 `/我的备份` |
| 递归子目录并保留目录结构 | 子目录会映射到 115 目标目录下 |
| 扫描间隔（秒） | 定时兜底扫描，默认 60 |
| 秒传探测次数 | 默认 3，设为 0 表示直接普通上传 |
| 失败后重试间隔（秒） | 本次探测失败返回后，等待多久再探测下一次 |
| 文件稳定时间（秒） | 文件多久没有变化才上传，避免上传正在复制的文件 |
| 只处理这些后缀 | 例如 `.mkv,.mp4`，留空表示全部 |
| 上传成功后删除本地文件 | 默认关闭 |
| 首次启用时也上传目录中已有文件 | 默认关闭；关闭时会把已有文件记为 `skipped`，之后新增或变化的文件才上传 |

## 详情页

详情页固定高度，列表区域固定高度并可滚动，每页 10 条，支持上一页/下一页：

- 状态、本地文件、大小、远端路径、上传方式、重试次数、错误、更新时间
- 失败和待处理记录可以点“重试”
- 任意记录可以点“删除”
- 顶部可以“立即扫描”和“清理成功记录”
- 操作完成后页面会自动重新加载
- 底部预留了设置按钮的空间，不会被浮动按钮遮挡

注意：

- 删除记录不会删除网盘文件。
- 如果本地文件仍然存在，删除记录后下一轮扫描会把它当成新文件重新上传。
- 清理成功记录同理；只想停止上传时，请删除本地文件或把文件移出监控目录。

## 注意事项

1. 插件使用 115 存储适配器的底层接口；主程序升级后如果 `u115.py` 接口变化，插件可能需要同步适配。
2. 115 有访问频率限制，探测次数不要设太大，失败后重试间隔建议至少 5 秒。
3. 全部探测失败后会调用宿主 `U115Pan.upload()` 做普通上传；该调用内部会再探测一次秒传，并重新计算一次 SHA1。
4. 如果 MoviePilot 运行在 Docker 中，监控目录必须填写容器内路径，不是宿主机路径。
5. watchdog 在 SMB/NFS/FUSE 等网络挂载上可能收不到内核事件；定时扫描会兜底，不会漏文件。
